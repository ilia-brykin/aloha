# Client Aloha Vue

Используй готовые возможности Aloha-Vue и проверяй API установленной версии. Этот skill описывает использование фреймворка в приложении, а не разработку его внутренних компонентов.

## Источники и связанные skills

Найди установленный пакет `aloha-vue` или его исходники в рабочем пространстве. Все пути к документации ниже относительны корню этого пакета, а не проекта клиента.

Сначала прочитай `AGENTS.md` пакета. Затем открывай только относящиеся к задаче страницы `llms/`: API компонентов находится в `llms/components/`, стили — в `llms/css/`, plugins — в `llms/plugins/`, функции — в `llms/functions/`.

Если документация неполна, проверь `src/index.js`, реализацию нужного компонента в `src/`, его типы в `types/aloha-vue.d.ts` и стили в `scss/`. Не угадывай props, события, slots и CSS-переменные. Не переноси API другой версии без проверки.

Для структуры кода, шаблонов и стилей следуй соглашениям клиентского проекта.

Для модальных форм и подтверждений дополнительно читай [client-aloha-vue-modal](../client-aloha-vue-modal/SKILL.md).

## Компоненты и подключение

Перед созданием собственного элемента проверь, решает ли задачу компонент Aloha-Vue. Предпочитай подходящий компонент и его публичный API, а не копирование разметки и внутренней логики.

Импортируй компоненты из `aloha-vue` и регистрируй локально. В Pug используй kebab-case, например `a-button` и `a-modal-form`.

Проверь существующую инициализацию приложения. Добавляй только необходимые plugins, не подключай их повторно и не меняй настройки всего приложения ради одного компонента. Общие настройки компонентов задаются через `AComponentsPlugin`, если настройка действительно общая.

## Тексты и иконки

Пользовательские тексты оформляй через систему переводов проекта. Aloha-Vue поддерживает ключи переводов в текстовых props, `ATranslation` для собственной разметки и `getTranslatedText` для строк в JavaScript. Учитывай, что неизвестный ключ может отображаться как обычный текст: проверяй загрузку словарей.

Сохраняй механизм смены языка проекта. Не требуй серверной таблицы переводов или конкретного формата ключей.

Иконки должны быть зарегистрированы в `AIconPlugin` под используемыми именами. Перед добавлением регистрации проверь существующие. Не оставляй кнопки только с иконкой без доступного названия.

## HTTP, уведомления и подтверждения

Используй существующую конфигурацию `AHttpPlugin` и `AHttpAPI` для запросов приложения. Проверь фактические параметры и результат нужного метода по исходникам, если страницы документации нет. Не задавай собственный base URL, CSRF-механизм или формат серверных ошибок по примеру другого проекта.

Учитывай глобальные callbacks ошибок. Если ошибку обрабатывает форма, проверь, как выбранные настройки позволяют ей получить отказ запроса и завершить загрузку. Не скрывай ошибки и не оставляй незавершённый Promise из-за неверного callback.

Для уведомлений используй `ANotificationAPI`, для простых подтверждений — `AConfirmAPI`. Проверь наличие соответствующих компонентов вывода в приложении, не добавляй их дубликаты в каждую страницу. Подробности смотри в `llms/components/notification.md` и `llms/components/confirm.md`.

## Стили и доступность

Предпочитай настройки компонентов, готовые классы `a_` и CSS-переменные `--a_`. Сначала читай подходящую страницу `llms/css/` и раздел переменных компонента. Собственный SCSS добавляй только при отсутствии подходящего решения.

Сохраняй доступные названия, labels, клавиатурное управление и видимый фокус. Не обходи встроенную доступность собственной реализацией без необходимости.

## Проверка

Проверь импорты, регистрацию plugins и иконок, тексты, состояния загрузки и ошибки. Для изменения поведения обнови соответствующие тесты проекта; для интерфейса проверь затронутые состояния и клавиатурное управление. Выполни подходящие команды из `package.json` и сообщи о непроверенном.

Если пришлось написать универсальную возможность, которой нет в установленном Aloha-Vue, после выполнения задачи укажи в конце ответа кандидата для переноса: что добавлено, где и зачем это полезно фреймворку. Не меняй и не публикуй сам фреймворк без отдельного поручения.
