# AJsonEditor — концепция

Структурный редактор JSON для aloha-vue 3.x: дерево с правкой ключей и значений, текстовый режим, поиск, переменные, хуки и плагины. Доступность по WCAG 2.2 AA с первого дня.

Отличие от существующих компонентов:

| Компонент | Что делает |
|---|---|
| `AJson` | текст JSON в textarea, проверка синтаксиса |
| `AValidatedJson` | правка данных по заданным правилам (модальные окна) |
| `ATree` | показ иерархии, без правки значений |
| **`AJsonEditor`** | **дерево + текст, правка на месте, переменные, поиск, хуки, плагины** |

## Статус

Все этапы (§14) реализованы, плюс история: кнопки «назад», «вперёд», «сбросить» и список шагов. Отличия от концепции:

- **Удаление:** по умолчанию без подтверждения, с отменой (Ctrl+Z и кнопка «Отменить» в строке статуса). AConfirm включается через `confirm-remove` (`true` / `"containers"`), потому что он требует `AModalConfirm` в приложении.
- **Режим `code`:** своя `textarea` вместо `AJson`. `AJson` — полный элемент формы с меткой и ошибками, внутри редактора он мешал бы.
- **Меню строки (ADropdown):** рисуется только у активной строки и строки под мышью, чтобы тысячи строк оставались лёгкими.
- **Подсветка совпадений:** свой `<mark>`, а не `filterSearchHighlight` (нет `v-html`).
- **`load-children`:** хук срабатывает при раскрытии узла; плюс «показать ещё» для больших массивов (`array-page-size`).

## 1. Цели и границы

**Цели**
- Править любой JSON без знания синтаксиса: добавить, удалить, переименовать, поменять тип, переместить.
- Вставлять **свои переменные** (`{{ user.name }}`) в строки, с подсказкой, проверкой и предпросмотром подстановки.
- **Расширяемость:** свои типы значений, действия, проверки, отрисовка — через хуки, плагины и слоты.
- **Доступность:** полностью с клавиатуры и скринридером, без `role="application"`.
- Большие документы (10 000+ узлов) без тормозов.

**Не входит в первую версию:** совместное редактирование, diff двух документов, полный JSON Schema (только подмножество через хук, см. §7).

## 3. Модель данных

- **v-model** — обычное JS-значение (объект, массив или примитив). По props `model-type="string"` модель — строка JSON (как у `AJson`).
- Внутри документ один, путь узла — **JSON Pointer** (`/users/0/name`). Путь — ключ строки, id для ARIA, ключ истории и аргумент хуков.
- Дерево не копируется целиком на каждую правку: операции (`set`, `add`, `remove`, `move`, `rename`, `changeType`) меняют модель неизменяемо по пути и эмитят новую ссылку.
- **История:** стек операций (не снимков), `undo-limit` по умолчанию 100, группировка быстрых правок одного поля.
- **Плоский список видимых строк** (`flatten`) пересчитывается от раскрытых узлов и фильтра. Это основа для виртуализации и клавиатуры.

## 4. Режимы и вид

| Режим | Описание |
|---|---|
| `tree` (по умолчанию) | дерево-таблица: ключ, значение, тип, действия |
| `code` | текст JSON (AJson), ошибки синтаксиса со строкой и столбцом |
| `split` | дерево и текст рядом, выделение синхронно |
| `readonly` | просмотр: копирование, поиск, раскрытие, без правки |

**Внешний вид**
- Чистая таблица без рамок между ячейками, отступ уровней с тонкими направляющими линиями.
- Цвета типов из токенов: строка, число, boolean, null, переменная (бейдж-чип).
- Счётчик детей у свёрнутых узлов: `{ 4 }`, `[ 12 ]`.
- Плотность `compact` / `normal` (`--a_density`), тёмная тема через токены.
- Действия строки видны при наведении **и** при фокусе (не только при hover).
- Все цвета — CSS-переменные `--a_json_editor_*` (таблица в документации генерируется).

## 5. Функции

**Структура**
- Раскрыть / свернуть узел, **раскрыть всё / свернуть всё**, раскрыть до уровня N (`expand-level`), раскрыть путь к узлу.
- Добавить ключ / элемент (до, после, внутрь), дублировать, удалить, переименовать ключ.
- Поменять тип (string ↔ number ↔ boolean ↔ null ↔ object ↔ array) с сохранением значения, где возможно.
- Переместить: перетаскивание **и** клавиатура (Alt+↑/↓), вырезать/вставить.
- Сортировать ключи объекта, отсортировать массив по полю.

**Поиск**
- Поиск по ключам, значениям или обоим; учёт регистра; регулярное выражение (опция).
- Подсветка совпадений (`filterSearchHighlight`), авто-раскрытие пути к совпадению.
- «Следующее / предыдущее» (Enter / Shift+Enter, F3), счётчик «3 из 17» в live-регионе.
- Режим **фильтра**: показывать только совпадения и их родителей.

**Буфер обмена**
- Копировать значение, ключ, путь (JSON Pointer или точечный `users[0].name`), узел как JSON.
- Вставить JSON в узел с проверкой синтаксиса.

**Прочее**
- Отменить / повторить (Ctrl+Z / Ctrl+Y, Cmd на Mac).
- Форматировать / сжать (в режиме `code`), скачать как файл, загрузить файл (через хук).
- Статусная строка: путь выделенного узла (хлебные крошки, кликабельные), число узлов, ошибки.
- Ограничения: `max-depth`, `readonly-paths`, `hidden-paths`, `locked-keys` (нельзя удалить или переименовать).

## 6. Переменные

Переменные — именованные значения, которые вставляются в строки и подставляются при использовании.

**Синтаксис** (props `variable-pattern`, по умолчанию как у переводов библиотеки):
- в строке: `"Hello {{ user.name }}"`;
- целое значение — переменная: `"{{ order.total }}"`. Редактор показывает это как чип `order.total`, тип «переменная».

**Реестр** — props `variables`:
```js
[
  { name: "user.name", label: "_VAR_USER_NAME_", type: "string", example: "Anna", group: "_VAR_GROUP_USER_" },
  { name: "order.total", type: "number", example: 12.5, description: "_VAR_ORDER_TOTAL_DESC_" },
]
```
Или функция / Promise (загрузка с сервера, фильтр по пути узла): `variables: ({ path, query }) => Promise<Variable[]>`.

**Вставка**
- Ввод `{{` в строке открывает подсказку (combobox + listbox, как ASelect): поиск, группы, тип, пример.
- Кнопка «Вставить переменную» в строке и на панели инструментов.
- Значение-переменная выбирается и в выборе типа: «Переменная».

**Показ и проверка**
- Токены в строке подсвечены как чипы. Неизвестная переменная — ошибка «Неизвестная переменная user.nmae», с предложением похожей.
- Несовпадение типа (переменная `number` в поле, где ждут `boolean`) — предупреждение.
- **Предпросмотр:** переключатель «Показать с подстановкой» и `variable-values` (реальные или примерные значения). Чистая функция `resolveVariables(json, values)` экспортируется отдельно.

## 7. Расширяемость

### 7.1 Хуки (props-функции)

Каждый хук получает контекст `{ path, key, value, parent, document, operation }`. До-хуки могут вернуть `false` (отменить) или изменённое значение, sync или Promise.

| Хук | Когда |
|---|---|
| `before-change` / `after-change` | любая операция с узлом |
| `before-add` | добавление: можно задать значение по умолчанию |
| `before-remove` | удаление: например, подтверждение через AConfirm |
| `before-rename` | переименование ключа |
| `before-type-change` | смена типа |
| `validate-node` | своя проверка узла → строка, массив ошибок или `{ level: "warning" }` |
| `validate-document` | проверка всего документа (сюда же подключается JSON Schema) |
| `parse` / `stringify` | свой формат модели (JSON5, YAML через внешнюю библиотеку) |
| `get-node-actions` | дополнительные действия строки по пути и значению |
| `get-value-type` | определить свой тип узла (дата, цвет, ссылка…) |
| `on-select` | выделен узел |
| `load-children` | ленивая загрузка больших веток |

### 7.2 Плагины

Плагин — объект, его можно подключить глобально (`AJsonEditorPlugin`, как другие плагины) или передать через props `plugins`:

```js
export default {
  name: "color",
  // свой тип значения: определение, отрисовка, редактор, проверка
  types: [{
    name: "color",
    detect: value => typeof value === "string" && /^#[0-9a-f]{6}$/i.test(value),
    view: ColorChip,           // компонент для показа
    editor: AColorPicker,      // компонент для правки (v-model)
    validate: value => …,
  }],
  actions: [{ id: "toUpper", label: "_UPPER_", when: ({ value }) => typeof value === "string", run: ({ value }) => value.toUpperCase() }],
  toolbar: [{ id: "export", label: "_EXPORT_", icon: Download, run: ({ document }) => … }],
  hooks: { beforeRemove: … },
  i18n: { de: { … }, en: { … } },
};
```

Встроенные типы тоже реализованы как плагины (`string`, `number`, `boolean`, `null`, `object`, `array`, `variable`). Так внутренний и внешний код используют один API.

### 7.3 Слоты

- `value` / `value-{type}` — своя отрисовка значения;
- `key` — своя отрисовка ключа;
- `row-actions` — действия строки;
- `toolbar-prepend` / `toolbar-append`;
- `empty` — пустой документ;
- `status` — статусная строка.

### 7.4 Методы (expose)

`expandAll()`, `collapseAll()`, `expandToLevel(n)`, `expandPath(path)`, `focusPath(path)`, `search(query)`, `undo()`, `redo()`, `get(path)`, `set(path, value)`, `remove(path)`, `validate()`, `format()`, `setMode(mode)`.

## 8. Доступность

**Шаблон: WAI-ARIA treegrid** (дерево с ячейками: ключ, значение, действия), не `tree`: в строке есть редактируемые поля и кнопки.

**Разметка**
- `role="treegrid"`, `aria-label` / `aria-labelledby` (label компонента), `aria-describedby` (подсказка по клавишам, ошибки), `aria-readonly` в режиме `readonly`.
- Строка `role="row"` с `aria-level`, `aria-setsize`, `aria-posinset`, `aria-expanded` (у объектов и массивов), `aria-selected` при множественном выборе.
- Ячейки `role="gridcell"`, `aria-rowcount` / `aria-rowindex` при виртуализации.
- Название строки: «name, строка, Anna» (ключ, тип, значение); ошибка через `aria-describedby` и `aria-invalid` на поле.

**Клавиатура**
- Режим навигации:
  - ↑ / ↓ — строки;
  - → — раскрыть или перейти к первому ребёнку; ← — свернуть или перейти к родителю;
  - Home / End — первая и последняя строка;
  - `*` — раскрыть всех соседей (по APG);
  - Ctrl+→ / Ctrl+← — между ячейками строки.
- Enter / F2 — правка ячейки, Escape — отмена правки, Enter — сохранить.
- Insert / Ctrl+Enter — добавить; Delete — удалить (с подтверждением по props); Alt+↑ / ↓ — переместить.
- Ctrl+F — поиск, F3 / Shift+F3 — совпадения, F8 / Shift+F8 — ошибки; Ctrl+Z / Y — отменить / повторить; Ctrl+C — копировать узел.
- Один tab stop внутри дерева (roving tabindex), Tab ведёт к панели инструментов и дальше по странице.

**Объявления** (один live-регион `role="status"`):
- «Узел добавлен», «Удалено: name», «Отменено», «3 из 17 совпадений», «Раскрыто всё».

**Остальное**
- Видимый фокус (токены `--a_focus_ring`), контраст 4.5:1 для типов, цвет — не единственный признак: у типа есть текст или иконка с подписью.
- Перетаскивание всегда с клавиатурной альтернативой (WCAG 2.5.7).
- Подтверждение удаления — AConfirm; фокус возвращается на строку или соседа.
- Ошибки: сводка в AErrors-стиле со ссылками, которые переводят фокус на узел (`focusPath`).
- `prefers-reduced-motion` — без анимации раскрытия.

## 9. Проверка (валидация)

**Уровни:** `error` (блокирует, `aria-invalid`), `warning` (показывается, не блокирует), `info`.

**Источники проверок** (работают вместе, результаты складываются):
1. **Синтаксис** в режиме `code`: сообщение с номером строки и столбца, переход к месту ошибки, в дереве не применяется, пока текст неверный.
2. **Встроенные правила по путям** — props `rules`, без зависимостей:
   ```js
   {
     "/name": { required: true, type: "string", minLength: 2, maxLength: 50 },
     "/age": { type: "number", min: 0, max: 150, integer: true },
     "/email": { pattern: "^[^@]+@[^@]+$", message: "_EMAIL_INVALID_" },
     "/tags": { type: "array", minItems: 1, uniqueItems: true },
     "/users/*/role": { enum: ["admin", "user"] },   // * — любой индекс или ключ
     "/settings": { additionalKeys: false, keys: ["theme", "lang"] },
   }
   ```
3. **Подмножество JSON Schema** — props `schema` (`type`, `properties`, `required`, `enum`, `minimum`/`maximum`, `minLength`/`maxLength`, `pattern`, `items`, `additionalProperties`). Схема также подсказывает ключи при добавлении и допустимые типы.
4. **Переменные:** неизвестная переменная, несовпадение типа (§6).
5. **Хуки** `validate-node` / `validate-document` (sync/async) — для своих правил и полного JSON Schema через внешнюю библиотеку.

**Когда проверять** — props `validate-on`: `change` (по умолчанию: после каждой операции узла), `blur`, `submit` (только методом `validate()` / в `AForm`), `none`.

**Показ:**
- у строки: иконка + текст для скринридера, поле `aria-invalid` и `aria-describedby` на текст ошибки;
- у свёрнутого родителя: счётчик «2 ошибки внутри», чтобы ошибка не терялась;
- сводка ошибок (стиль AErrors) над деревом или в статусной строке: список ссылок «/users/0/email: неверный e-mail», клик переводит фокус на узел;
- кнопки «следующая / предыдущая ошибка» (F8 / Shift+F8);
- событие `validate` с `{ isValid, errors: [{ path, level, message }] }`, метод `validate()` возвращает то же. В `AForm` ошибки уходят в общую сводку.

**Props проверки:** `rules`, `schema`, `validateOn`, `showErrorSummary`, `errorSummaryPosition` (`top` | `status`), `blockInvalidSave` (не эмитить `update:modelValue` при ошибке синтаксиса), `maxErrors`.

## 10. Форматирование

Форматирование влияет на текст JSON: режим `code`, `modelType="string"`, копирование, скачивание. Кнопки «Форматировать» и «Сжать» на панели, методы `format()` / `minify()`, авто-форматирование по `format-on` (`blur` | `save` | `none`).

**Настройки через props** (объект `format-options` или отдельные props, отдельные важнее):

| Props | Значения | По умолчанию |
|---|---|---|
| `indent` | число пробелов или `"tab"` | `2` |
| `sortKeys` | `false` / `true` / `"asc"` / `"desc"` / функция `(a, b) => …` | `false` |
| `inlineArrays` | короткие массивы примитивов в одну строку: `false` / число (макс. длина строки) | `false` |
| `inlineObjects` | то же для маленьких объектов | `false` |
| `maxLineLength` | ориентир для `inline*` | `80` |
| `keyQuotes` | всегда `"double"` (JSON); `"none"`/`"single"` только с плагином JSON5 через `stringify` | `"double"` |
| `escapeUnicode` | `ä` вместо `ä` | `false` |
| `escapeSlashes` | `\/` | `false` |
| `lineEnding` | `"lf"` / `"crlf"` | `"lf"` |
| `trailingNewline` | перевод строки в конце | `false` |
| `spaceAfterColon` | `"key": 1` / `"key":1` | `true` |
| `emptyContainers` | `{}` / `{ }` | `"{}"` |
| `numberFormat` | функция для чисел при выводе (без потери точности по умолчанию) | — |
| `minify` | всегда компактно (без отступов) | `false` |

**Форматирование показа в дереве** (на данные не влияет): `display-formatters` — объект `тип → функция` или фильтр библиотеки (`filterDate`, `filterCurrency`), например даты по-местному, длинные строки с `filterTruncateMiddle` (полное значение — в title и для скринридера). Длинные строки: `string-max-length` для показа, полный текст в редакторе.

Чистые функции экспортируются отдельно: `formatJson(value, options)`, `minifyJson(value)`, `resolveVariables(value, values)`. Их можно использовать и без компонента.

## 11. Props (первая версия)

**Данные**
`modelValue`, `modelType` (`"object"` | `"string"`), `modelUndefined`, `readonly`, `disabled`, `mode` (`tree` | `code` | `split`), `modes` (какие доступны), `rootName`.

**Вид**
`expandLevel` (по умолчанию 1), `expandedPaths`, `showTypes`, `showCounts`, `showIndexes`, `showGuides`, `density`, `height`, `maxHeight`, `virtualThreshold` (с какого числа строк виртуализация), `pathFormat` (`pointer` | `dot`), `keyColumnWidth`.

**Правка**
`allowAdd`, `allowRemove`, `allowRename`, `allowTypeChange`, `allowMove`, `allowedTypes`, `confirmRemove`, `maxDepth`, `readonlyPaths`, `hiddenPaths`, `lockedKeys`, `sortKeys`, `undoLimit`.

**Проверка и форматирование:** см. §9 и §10.

**Поиск**
`searchable`, `searchIn` (`keys` | `values` | `both`), `searchCaseSensitive`, `searchRegex`, `searchFilter` (только совпадения), `searchDebounce`.

**Переменные**
`variables`, `variablePattern` (`{ open: "{{", close: "}}" }`), `variableValues`, `showResolved`, `allowUnknownVariables`.

**Хуки:** см. §7.1. **Плагины:** `plugins`.

**Форма:** стандартные props элементов формы, как у `AInputTags`: `id`, `htmlId`, `label`, `labelDescription`, `helpText`, `errors`, `required`, `change`, `isHide`, `isRender`, `extra`, `alwaysTranslate`…

**Тексты:** `toolbarLabel`, `keyboardHint` (ключи перевода по умолчанию).

**События:** `update:modelValue`, `change` (с операцией и путём), `select`, `expand`, `collapse`, `search`, `validate`, `mode-change`, `error`.

## 12. Производительность

- Плоский список видимых строк + виртуализация после `virtual-threshold` (по умолчанию 300 строк). При этом `aria-rowcount` / `aria-rowindex` обязательны.
- `load-children` для очень больших веток, «показать ещё 100» в массивах.
- Поиск с debounce, без пересчёта всего дерева на каждую букву: индекс путей строится один раз и обновляется по операциям.
- Операции по пути — O(глубина), без `JSON.parse(JSON.stringify())` всего документа.

## 13. Переиспользование

- `AJson` — режим `code`;
- `ASelect` — тип и выбор переменной (combobox);
- `AInput`, `AInputNumber`, `ASwitch` — редакторы значений;
- `ADropdown` — меню действий строки (WAI-ARIA menu, уже доступное);
- `AConfirm` — подтверждение удаления;
- `ATooltip` — подсказки кнопок;
- `filterSearchHighlight` — подсветка поиска;
- `AErrorsText` — ошибки;
- `ADateInput` / `AColorPicker` — как пример плагинов типов (`date`, `color`).

## 15. Открытые вопросы

1. Название: `AJsonEditor` или расширить существующий `AJson` (режимы `tree` / `code`)? *Рекомендация:* новый компонент, а `AJson` использовать внутри как режим `code`. Так текущие пользователи `AJson` ничего не теряют.
2. Синтаксис переменных по умолчанию: `{{ name }}` (как переводы) или `${name}`? *Рекомендация:* `{{ }}` с props `variable-pattern`.
3. JSON Schema: только через хук `validate-document` (без зависимости) или встроить поддержку подмножества (type, required, enum, min/max)? *Рекомендация:* подмножество во втором этапе, полный Schema — через хук и внешнюю библиотеку.
4. Удаление: подтверждать всегда, никогда или только для объектов и массивов (`confirm-remove: "containers"`)? *Рекомендация:* только контейнеры + отмена через Ctrl+Z и сообщение «Удалено, Ctrl+Z — отменить».
